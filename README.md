# Jev vs LLM Connect Four



## Configure

Use a Bedrock long-term API key and a TypeSafe AI key:

```bash
export AWS_BEARER_TOKEN_BEDROCK=YOUR_BEDROCK_TOKEN
export TYPESAFE_API_KEY=YOUR_TYPESAFE_TOKEN
```

Startup fails before model checks or server initialization if either variable is missing or blank.

Optionally restrict the user-visible models independently by backend with comma-separated runtime model IDs:

```bash
export CONVERSE_MODELS=zai.glm-4.7-flash,qwen.qwen3-32b-v1:0,moonshotai.kimi-k2.5
export MANTLE_MODELS=minimax.minimax-m2.5,mistral.devstral-2-123b,xai.grok-4.3
```

Only models verified to support native JSON-schema structured output on their configured backend are coded as selectable. AWS documents Mantle structured outputs for `xai.grok-4.3`, which uses the `/openai/v1/chat/completions` API base. AWS also documents structured outputs for Kimi K2.5 through Bedrock Runtime, so `moonshotai.kimi-k2.5` is selectable through Converse rather than Mantle; Claude Haiku 4.5 is already selectable through Converse as `global.anthropic.claude-haiku-4-5-20251001-v1:0`. The requested `anthropic.claude-opus-5`, `anthropic.claude-haiku-4-5`, and `openai.gpt-5.6` Mantle IDs remain in coded diagnostics but are not selectable: AWS explicitly marks both Claude models unsupported on Mantle and does not document Mantle structured-output support for the GPT ID. When either variable is unset, all selectable models for that backend remain candidates. Configured IDs are still intersected with the coded catalog and the models available to the Bedrock API key; unknown, wrong-backend, structured-output-incompatible, and unavailable IDs are logged and omitted from the selector.

## Run

```bash
./sbt dev
```

### Anonymous API safety

The public API has no prompt or generic inference endpoint. A game start accepts
only a catalog-approved model ID and `jev` or `llm` as the opening player; all
provider messages and board states are generated by the server. Start bodies
are limited to 1 KiB. Uncached games are allowed, but paid work is bounded to
four concurrent computations, one in-flight computation per model/opening
matchup, and eight new uncached starts per rolling minute. Cached replays do not
consume that paid-start budget. Bedrock turns are capped at 256 output tokens,
except MiniMax M2.5, whose reasoning model needs a 2,048-token budget to emit
its final structured response. A Connect Four game has at most 42 turns. Active sessions and retained game history are
also bounded. Provider credentials never appear in responses or recorded
request details.

### Test local library changes

With `zio-typesafe-ai` and/or `zio-bedrock` checked out next to this project, pass `-Dlocal` to use each available sibling root project instead of its published artifact:

```bash
./sbt -Dlocal test
```

Without `-Dlocal`, or when a sibling checkout does not exist, the build independently uses that library's published dependency.

### Run Jev prompt experiments

The live experiment matrix compares alternative state, instruction, criteria, candidate-board, and decomposed-question formulations against known win/block positions. It is skipped during normal tests and requires an explicit gate:

```bash
./sbt -Dlocal 'set Test / envVars += ("RUN_JEV_PROMPT_EXPERIMENTS" -> "1"); testOnly JevPromptExperimentSpec'
```

Experiment failures are measurements: each failed test reports the expected and selected columns, while `JEV_PROMPT_EXPERIMENT` log lines include confidence and decomposition traces. To run selected variants only:

```bash
./sbt -Dlocal 'set Test / envVars ++= Map("RUN_JEV_PROMPT_EXPERIMENTS" -> "1", "JEV_PROMPT_VARIANTS" -> "production-structured,decomposed-parallel-questions"); testOnly JevPromptExperimentSpec'
```

Available variant names are defined in `JevPromptExperimentSpec.scala`. Diagnostic tracks include `state-transition-probes`, `intent-routed-fan-out`, `confidence-gated-intent-routing`, and `candidate-composite-scoring`; their traces expose intermediate state recognition, intent, specialist choices, confidence, and weighted candidate dimensions. Representation tracks include true 2D matrix state, 2D post-move candidate matrices, row-labeled ASCII, and generic ASCII winning-shape examples. Defense tracks include committed prose without option facts, verbose structured/string guidance, exhaustive simulation instructions, and verbose guidance with ASCII candidates. Production intentionally uses the smallest shared protocol: six compact top-to-bottom rows, two general Connect Four rules, one goal, and the same playable `column_N` options for both providers. Jev receives those options as one TypeSafe `Choice`; Bedrock receives the same state, prose, and options as its user message with native structured output. The more tactical protocols remain experiments rather than production behavior. Use `JEV_PROMPT_SCENARIOS` as another comma-separated filter when only selected boards should run.

### Run Jev understanding diagnostics

The understanding suite asks 78 independent questions per board to measure cell reading, legal moves, gravity, one-step wins for both players, opponent replies after each candidate, and tactical intent. It is also skipped unless explicitly enabled:

```bash
./sbt -Dlocal 'set Test / envVars += ("RUN_JEV_UNDERSTANDING_DIAGNOSTICS" -> "1"); testOnly JevUnderstandingDiagnosticSpec'
```

Use `JEV_DIAGNOSTIC_SCENARIOS` to select comma-separated boards. `JEV_UNDERSTANDING` logs category totals, while `JEV_UNDERSTANDING_MISMATCH` logs every expected/actual mismatch with its raw probability or confidence.

## Deploy to Heroku

This app uses `heroku/jvm` followed by `https://github.com/jamesward/buildpack-scala`. The buildpack stages the native-packager app, turns that staging directory into the slug root, and automatically runs the generated `bin/jev-llm-connect-four` launcher—no `Procfile` is needed.

The server binds to all interfaces and uses the `PORT` environment variable when present. Configure both API keys and keep one web dyno because active games are in memory:

```bash
heroku config:set --app jev-llm-c4 \
  AWS_BEARER_TOKEN_BEDROCK=YOUR_BEDROCK_TOKEN \
  TYPESAFE_API_KEY=YOUR_TYPESAFE_TOKEN
heroku ps:scale --app jev-llm-c4 web=1
```
